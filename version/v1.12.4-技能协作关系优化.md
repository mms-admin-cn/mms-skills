# v1.12.4-技能协作关系优化

## 背景与目标

所有任务被强制走完整流水线（brainstorming → writing-plans → subagent → review → finish），即使修改一个按钮颜色也要过 9 步设计流程。同时 brainstorming 和 mms-dev-workflow 各自产出不同位置的设计文档，互相打架。Codex 无原生 `Skill` 工具导致反复重试加载。

目标：建立按复杂度分级的工作流，消除技能间冲突，让简单任务快、复杂任务稳。

## 核心修改

### 1. superpowers/SKILL.md — 任务分级系统 `<TASK-TIERING>`
- **Level 0（琐碎）**：改颜色/配置/拼写 → 直接改，不走任何流程
- **Level 1（简单）**：单 bug 修复/加字段 → 快速分析+直接实施+TDD
- **Level 2（中等）**：新功能/新页面 → mms-dev-workflow 完整流程
- **Level 3（复杂）**：新子系统/架构变更 → brainstorming → writing-plans 全流程
- 用户说"快速改" → 直接降级到 Level 0/1

### 2. 解决 brainstorming ↔ mms-dev-workflow 冲突
- brainstorming：绿野/新产品/从零搭建（Level 3）
- mms-dev-workflow：已有项目功能迭代（Level 2）
- 明文规定：一个任务只用一套，不同时产出两份设计文档

### 3. Codex 平台适配
- 明确告知 Codex 没有原生 `Skill` 工具，用 `Read` 替代
- 禁止反复重试不存在的工具调用

### 4. 用户指令优先权落地
- 用户说"快速改"/"不用走流程" → 立即跳过流程技能
- 不再用 "instructions say WHAT not HOW" 堵回去

### 5. Red Flags 表更新
- "The skill is overkill" → 改为引用 TASK-TIERING 判断

## 影响范围
- `superpowers/SKILL.md`：核心改动，新增分级+Codex适配
- `brainstorming/SKILL.md`：增加使用/不使用边界
- `mms-dev-workflow/SKILL.md`：增加适用层级+与brainstorming分工
- `AGENTS.md`：增加复杂度分级指引
- `CLAUDE.md`：同步更新

## 验收标准
- 修改按钮颜色 → 直接改，不触发任何流程技能
- 新增登录功能 → 走 mms-dev-workflow，不触发 brainstorming
- 构建支付系统 → 走 brainstorming → writing-plans 全流程
- Codex 不再因 `Skill` 工具缺失而重试卡死
- 用户说"快速改" → 立即跳过流程
