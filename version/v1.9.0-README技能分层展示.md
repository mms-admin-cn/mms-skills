# v1.9.0-README技能分层展示

## 背景与目标

README 已列出 20 款特色实用技能，但当前表格是平铺清单。用户确认需要按“核心技能”和“生态增强技能”做分层，让之前已安装的 Oh My Claude Code、Superpowers、Everything Claude Code、UI/UX Pro Max、Playwright MCP 等技能更容易被看到，也避免它们被误认为缺失。

本次目标是优化 README 技能展示结构，把 MMS 日常开发主链路和生态增强能力分开说明，并更新项目版本。

## 需求范围

### 本次包含

- 版本递增到 `v1.9.0`。
- 更新 `PROJECT_VERSION` 与 `mms-skills.json`。
- 重构 README 的 20 款特色技能清单为两层：MMS 核心技能、生态增强技能。
- 在生态增强层明确展示用户关心的 10 款已安装技能。

### 本次不包含

- 不安装新技能。
- 不修改具体技能正文。
- 不调整三端安装方式。

## 实施步骤

1. 创建本版本文档。
2. 更新项目版本标识。
3. 重写 README 的 20 款技能清单结构。
4. 同步英文 README 版本号。
5. 验证 README 分组和版本一致性。

## 风险与回滚

- 风险：分层后用户误以为生态增强技能不重要。
  - 处理：明确生态增强技能用于协作、质量、UI、测试、资料检索和内容治理，是按场景触发而不是默认全开。
- 风险：表格过长导致 README 难读。
  - 处理：保留每条的短介绍和使用方法，不复制技能正文。
- 回滚：恢复 README 技能清单、`PROJECT_VERSION`、`mms-skills.json`，删除本版本文档。

## 验收标准

- README 顶部版本显示 `v1.9.0`。
- README 中存在“MMS 核心技能”和“生态增强技能”两个小节。
- 两个分组合计仍展示 20 款技能。
- 用户提到的 10 款技能均在 README 中可见。
- `PROJECT_VERSION` 与 `mms-skills.json` 版本一致。

## 验证结果

- `PROJECT_VERSION` 已更新为 `v1.9.0`，并通过版本一致性检查。
- `mms-skills.json` 已更新为 `version: v1.9.0`，Node 读取验证通过。
- `README.md` 已按“MMS 核心技能”和“生态增强技能”两层展示。
- 已验证 MMS 核心技能 `10` 条、生态增强技能 `10` 条，合计 `20` 条。
- 用户提到的 `oh-my-claudecode`、`superpowers`、`everything-claude-code`、`frontend-design`、`ui-ux-pro-max`、`playwright-mcp`、`agent-reach`、`humanizer-zh`、`content-risk-detector`、`skill-creator` 均已在 README 中可见。
- `README.en.md` 版本号和自检命令已同步为 `v1.9.0`。

## 复盘沉淀

- README 的技能入口不应只按“好用程度”平铺，分成“主链路”和“增强能力”后更利于 Agent 选择合适上下文。
- 生态增强技能通常能力很强但上下文较重，README 中要提示“按场景触发，不默认全开”。
- 用户关心的已安装技能需要在 README 明确出现，否则即使已经安装，也容易被误认为缺失。
