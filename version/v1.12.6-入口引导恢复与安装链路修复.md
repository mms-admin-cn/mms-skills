# v1.12.6-入口引导恢复与安装链路修复

## 背景与目标

v1.12.5 已经把技能触发策略调整为“默认不加载技能，按任务复杂度分级”，方向正确，但最新提交中 `AGENTS.md`、`CLAUDE.md`、`.cursorrules`、`.cursor/rules/00-project-bootstrap.mdc` 被清空，导致 `install.sh` 安装后目标项目拿不到任何引导规则。

同时，安装脚本存在全局安装顺序、空文件校验、全局 Claude 路径和 Cursor 验证提示等问题，影响 Codex / Cursor / Claude Code 三端落地。

本次目标：恢复入口引导，保留轻量任务分级策略，修复安装脚本，确保安装后对话流畅、不再出现技能互相抢流程。

## 需求范围

- 恢复 Codex、Claude Code、Cursor 的入口引导文件。
- 明确纯问候、Level 0/1 小任务不加载技能。
- 明确 Level 2/3 才进入 `mms-dev-workflow` / `brainstorming` 等流程。
- 修复 `install.sh` 的 `--all`、`--global`、`--shell`、空文件和验证提示问题。
- 更新版本号到 `v1.12.6`。

## 实施步骤

1. 重写入口文件，统一任务分级、技能根目录和优先级规则。
2. 调整 `install.sh` 参数展开顺序，先处理 `--all`，再处理全局安装。
3. 安装时拒绝复制空入口文件，并支持绝对路径目标。
4. 修正全局 Cursor / Claude Code 安装路径与验证提示。
5. 使用临时目录验证 Codex、全量项目安装和全局安装。
6. 安装到当前项目，确认 `AGENTS.md` 非空且路径已替换。

## 风险与回滚

- 风险：入口规则过强会再次导致小任务卡顿。
  - 处理：入口规则以“默认不加载技能”为第一原则，只有明确 Level 2/3 或领域任务才读技能。
- 风险：全局安装写入 shell 配置影响用户环境。
  - 处理：仅追加 `MMS_SKILLS_HOME`，已存在时跳过，并给出 source 提示。
- 回滚：恢复 v1.12.5 前状态或回退本次提交即可。

## 验收标准

- `install.sh --codex --target <tmp>` 安装出的 `AGENTS.md` 非空。
- `install.sh --all --target <tmp>` 安装三端入口且文件非空。
- `install.sh --global --all` 在干净 HOME 下不报错，Cursor / Claude Code 路径正确。
- 当前项目重新安装后，`AGENTS.md` 能指向可访问的 `skills-shared/`。
- 入口规则明确“在吗 / 谢谢 / 改颜色 / 小 bug”不触发完整技能流程。

## 复盘沉淀

- 技能库入口文件必须纳入安装脚本的非空校验，避免“安装成功但无规则”。
- 安装脚本新增能力后，应至少跑临时目录安装用例，覆盖单平台、全平台、全局安装三类路径。
- 入口规则应只做路由和优先级，不复制技能正文，避免 SSOT 失效。
