# v1.7.0-项目版本标识与README安装入口

## 背景与目标

当前项目已经沉淀为 `Cursor / Codex / Claude Code` 共用的技能库，但根 README 仍偏内部说明，缺少醒目的版本标识、安装入口和使用路径。新接入的软件或 Agent 需要快速判断项目用途、当前版本、技能根目录、安装方式和执行规范。

本次目标是补齐项目级版本标识，并优化根 README，让任何软件或人员打开仓库首页后都能一眼知道如何安装、如何接入、如何使用。

## 需求范围

### 本次包含

- 新增项目版本标识文件。
- 新增机器可读项目清单，标明名称、版本、技能根目录和入口文件。
- 重构根 `README.md`，包含项目定位、版本、目录结构、安装命令、三端接入、使用流程、维护规则和验证方式。
- 说明 `skills-shared/` 是唯一技能来源，避免多端重复维护。

### 本次不包含

- 不调整具体技能内容。
- 不处理工作区已有的其他未提交修改或删除。
- 不发布 npm / pip / composer 等包。

## 实施步骤

1. 确认当前版本序列，递增到 `v1.7.0`。
2. 新增版本文档。
3. 新增项目版本标识与机器可读清单。
4. 优化根 README 的安装与使用说明。
5. 验证 README 链接、版本号与清单一致。

## 风险与回滚

- 风险：根目录已有 `version/`，在大小写不敏感文件系统上无法再创建 `VERSION` 文件。
  - 处理：使用 `PROJECT_VERSION` 和 `mms-skills.json` 承载版本标识。
- 风险：安装命令使用绝对路径会限制跨机器使用。
  - 处理：README 同时提供 `MMS_SKILLS_HOME` 变量方式和当前机器绝对路径方式。
- 回滚：删除本次新增的版本标识文件和清单，恢复 `README.md`，删除本版本文档。

## 验收标准

- 仓库根目录存在可读版本标识。
- 仓库根目录存在机器可读清单。
- `README.md` 顶部展示当前版本。
- README 包含 Cursor、Codex、Claude Code 的安装命令和使用流程。
- README 明确 `skills-shared/` 是唯一技能来源。

## 验证结果

- `PROJECT_VERSION` 已写入 `v1.7.0`，并通过 `test "$(cat PROJECT_VERSION)" = "v1.7.0"` 验证。
- `mms-skills.json` 已写入 `version: v1.7.0`、`skillsRoot: skills-shared`、三端入口文件与默认工作流技能，并通过 Node 读取验证。
- 根 `README.md` 已重构，包含版本徽标、快速识别、目录结构、安装命令、三端接入、使用流程、版本规则、维护规范和自检命令。
- `README.en.md` 已从占位模板更新为当前版本的英文快速入口，避免平台或软件默认读取英文 README 时看到旧信息。
- 当前 `skills-shared/` 扫描到 `84` 个 `SKILL.md`。
- 已验证 `skills-shared/` 下不存在缺少 `SKILL.md` 的一级技能目录。

## 复盘沉淀

- 项目已有 `version/` 目录，在大小写不敏感文件系统上会与传统 `VERSION` 文件冲突；后续统一使用 `PROJECT_VERSION` 作为人可读版本文件，使用 `mms-skills.json` 作为机器可读清单。
- README 的首屏要优先回答“这是什么、当前版本、从哪里安装、怎么接入、怎么验证”，再展开维护规则；这样对 Agent 和人都更友好。
- 安装命令应使用 `MMS_SKILLS_HOME` 变量承载仓库位置，同时保留当前推荐绝对路径，兼顾本机自动执行和跨机器迁移。
- 多语言 README 需要同步最低限度的版本、安装和验证信息，否则平台自动选中英文 README 时会误导新接入软件。
