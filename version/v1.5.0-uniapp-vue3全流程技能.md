# v1.5.0-uniapp-vue3全流程技能

## 背景与目标

用户希望新增一个面向 `uni-app Vue3` 的工作流技能，把需求分析、方案设计、脚手架创建、依赖安装、运行环境管理、自动化测试、打包发布和服务器部署串成一条连续流程，减少反复向用户索要命令。

这个技能要结合现有共享技能库中的 `mms-dev-workflow`、`hbuilderx-automation`、`env-manager`、`api-tester`、`mms-ssh-connect`、`mms-desktop` 等能力，在普通 `uni-app Vue3` 项目中默认推进完整交付，而不是停留在单点命令指导。

## 需求范围

### 本次包含

- 新建 `skills-shared/uniapp-vue3-workflow/` 技能。
- 结合 uv-ui 官方文档、插件市场页面与 HBuilderX CLI 能力，形成可执行工作流。
- 把 `create-uni`、HBuilderX 导入/运行、uv-ui 接入、环境变量管理、测试、打包、部署放进同一套技能。
- 将 uv-ui API 工具库纳入默认开发策略，常见工具函数优先使用 `uni.$uv` 或局部引入，减少重复封装。
- 更新 `skills-shared/README.md` 的技能索引。
- 视需要同步到本机 `~/.codex/skills/`，保证当前 Codex 会话可直接使用。

### 本次不包含

- 不修改任何业务项目源码。
- 不新增 uni-app X 专用规则。
- 不替代现有 `hbuilderx-automation`、`env-manager`、`api-tester`、`mms-ssh-connect` 等技能，只做编排与入口收敛。

## 实施步骤

1. 调研 uv-ui 官方安装、扩展配置与资源入口。
2. 调研 HBuilderX CLI 能力，确认哪些命令可直接用于导入、运行、发布、打包、日志和插件管理。
3. 创建版本文档，记录边界。
4. 新建 `skills-shared/uniapp-vue3-workflow/SKILL.md`，明确默认工作流。
5. 补充参考资料，固化可复用命令、安装/配置要点与 uv-ui API 工具清单。
6. 更新 `skills-shared/README.md` 索引。
7. 复制到本机安装副本并验证触发词。

## 风险与回滚

- 风险：把 HBuilderX 能力误写成“能负责脚手架创建”，导致技能描述失真。
  - 处理：明确脚手架创建由 `create-uni` 负责，HBuilderX 负责导入、运行、打包、发布。
- 风险：uv-ui 接入方式在 HBuilderX 导入与 npm 安装之间混淆。
  - 处理：在技能里分开写明，默认优先 HBuilderX 插件市场导入到 `uni_modules`。
- 风险：技能过于发散，重新把用户拉回“手把手下命令”。
  - 处理：把问题拆成分析、设计、实现、验证、部署五段，默认直接推进，只在真正缺失信息时提问。
- 回滚：删除 `skills-shared/uniapp-vue3-workflow/` 目录，恢复 `skills-shared/README.md` 的新增索引；若同步了 `~/.codex/skills/`，同时删除对应安装副本。

## 验收标准

- `skills-shared/uniapp-vue3-workflow/SKILL.md` 存在，并能覆盖 uni-app Vue3 的端到端工作流。
- 技能中明确包含 `create-uni`、HBuilderX、uv-ui、环境变量、测试、打包、部署、服务器同步等流程。
- 技能中明确要求常见节流防抖、对象处理、时间格式化、路由跳转、参数拼接、校验、随机值、节点信息等优先使用 uv-ui API 工具库。
- `skills-shared/README.md` 中出现该技能的触发索引。
- 当前 Codex 可见的安装副本中也能命中该技能。

## 验证结果

- 已验证 `create-uni` CLI 支持 `--ts`、`-ui`、`-e`、`--gui` 等选项。
- 已验证 HBuilderX CLI `v5.07.2026041006` 支持 `project open`、`uni_modules --download/--upgrade`、`launch web/app/mp`、`logcat`、`screencap`、`publish web/app/mp`、`pack`、`hosting deploy`。
- 已确认 HBuilderX CLI 帮助中没有普通项目脚手架创建命令，因此技能采用 `create-uni` 创建，HBuilderX 导入运行。
- 已确认 uv-ui 插件市场 ID 为 `uv-ui`，支持 `uni_modules` 导入；npm 包为 `@climblee/uv-ui`。
- 已把 uv-ui API 工具库纳入技能默认策略，优先使用 `uni.$uv` 或局部引入。

## 复盘沉淀

- HBuilderX 是运行、导入、发布与打包工具，不应强行描述成脚手架生成器；脚手架创建交给 `create-uni` 更稳。
- uv-ui 不只是组件库，还提供 API 工具和主题/基础样式能力；技能应把工具库列为默认优先项，避免重复造函数。
- 全流程技能应负责“编排其他技能”，不是复制其他技能的全部细节；这样后续一句需求才能自然推进到验证和部署。
