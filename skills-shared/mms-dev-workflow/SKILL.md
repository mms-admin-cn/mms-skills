# mms 统一研发工作流

## 适用层级（参照 superpowers TASK-TIERING）
- **Level 2（中等功能）**：完整执行全部 5 阶段
- **Level 0/1（琐碎/简单）**：跳过此技能，直接实施
- **Level 3（复杂系统）**：改用 brainstorming → writing-plans 流水线，本技能只做复盘沉淀

## 与 brainstorming 的分工
- **新项目/新产品/从零搭建** → 使用 brainstorming（产出 `docs/superpowers/specs/`）
- **已有项目的功能迭代** → 使用 mms-dev-workflow（产出 `version/vX.Y.Z-xxx.md`）
- **两套不混用**：一个任务只用其中一套设计流程，不同时产出两份设计文档

## 执行规范
1. 全程使用简体中文沟通与输出（代码/命令/日志原文除外）。
2. 新功能开发前先做需求分析。
3. 分析通过后，在项目根目录 `version/` 新建版本文档，再开始开发。
4. 版本文档命名带版本号并递增：`v主.次.修订-功能说明.md`。
5. 开发过程中同步任务进度（状态、阻塞、下一步）。
6. 完成后做复盘，将可复用经验沉淀到 `skills-shared/`。

## 退出条件
以下情况立即退出本流程，不做版本文档和复盘：
- 用户说"快速改""直接改""just do it"
- 改动范围明显是 Level 0 或 1
- 用户中途取消或改变方向

## 标准流程

### 阶段A：需求分析
- 明确目标、范围、边界、验收标准。
- 输出：人话版方案（模块关系、数据流、状态变化）。

### 阶段B：版本文档创建（先于开发）
- 目录：`version/`
- 文件：`vX.Y.Z-xxx.md`
- 文档最少包含：
  - 背景与目标
  - 需求范围
  - 实施步骤
  - 风险与回滚
  - 验收标准

### 阶段C：开发执行
- 按需求文档逐项落地。
- 发生范围变更时，先更新版本文档再改代码。

### 阶段D：进度同步
- 任务状态：`pending / in_progress / completed / blocked`
- 每次关键变更后同步：当前进度、阻塞点、下一步。

### 阶段E：复盘沉淀（自我进化）
- 记录本次有效做法、踩坑、可复用模式。
- 将可复用方法沉淀到 `skills-shared/` 对应技能中。

## 触发词
- "开始新功能"
- "按规范开发"
- "先出版本文档再开发"
