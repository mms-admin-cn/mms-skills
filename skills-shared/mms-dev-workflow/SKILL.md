# mms 统一研发工作流

## 强制规范
1. 全程使用简体中文沟通与输出（代码/命令/日志原文除外）。
2. 每个新功能开发前，必须先做需求分析。
3. 分析通过后，必须先在项目根目录 `version/` 新建版本文档，再开始开发。
4. 版本文档命名必须带版本号并递增：`v主.次.修订-功能说明.md`。
5. 开发过程中必须同步任务进度（状态、阻塞、下一步）。
6. 完成后必须做复盘沉淀，更新技能经验（自我进化）。

## 标准流程

### 阶段A：需求分析
- 明确目标、范围、边界、验收标准。
- 输出：人话版方案（模块关系、数据流、状态变化）。

### 阶段B：版本文档创建（先于开发）
- 目录：`version/`
- 文件：`vX.Y.Z-xxx.md`
- 文档最少包含：
  - 背景与目标
  - 需求范围
  - 实施步骤
  - 风险与回滚
  - 验收标准

### 阶段C：开发执行
- 按需求文档逐项落地。
- 发生范围变更时，先更新版本文档再改代码。

### 阶段D：进度同步
- 任务状态：`pending / in_progress / completed / blocked`
- 每次关键变更后同步：当前进度、阻塞点、下一步。

### 阶段E：复盘沉淀（自我进化）
- 记录本次有效做法、踩坑、可复用模式。
- 将可复用方法沉淀到 `skills-shared/` 对应技能中。
- 当任务是“把稳定文档沉淀成技能”时：保留源文档路径、抽取触发词、写清调用时机、补共享索引关联，避免只复制文档而不能被后续任务命中。
